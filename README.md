# time_entries_Ana

This repository pulls time-tracking data from the ClickUp API, writes intermediate datasets into the `DB/` folder, publishes selected CSV files back to GitHub through GitHub Actions, and serves those CSVs as the source for a Power BI report.

## Business context

The reporting flow is:

1. ClickUp is the source system for time entries and task metadata.
2. GitHub Actions runs the extraction scripts on weekdays and updates the CSV files stored in this repository.
3. Power BI connects to the CSV files in GitHub.
4. The Power BI user manually clicks `Refresh` in the report to pull the latest published CSV data.

## How the repository works

The scripts are organized as a batch pipeline:

- `scripts/tasks.py` builds `DB/tasks_table.csv`, which is used as a lookup table for ClickUp task-to-project mappings.
- `scripts/clients_time_entries.py` downloads time entries for the client services space and writes `DB/clients_time_entries.db`.
- `scripts/content_time_entries.py` downloads time entries for the content space and writes `DB/content_time_entries.db`.
- `scripts/dev_time_entries.py` downloads time entries for the dev space and writes `DB/dev_time_entries.db`.
- `scripts/non_billable_time_entries.py` downloads time entries for the non-billable space and writes `DB/non_billable_time_entries.db`.
- `scripts/off_page_content_time_entries.py` downloads time entries for the off-page content list and writes `DB/off_page_content_time_entries.db`.
- `scripts/all_time_entries.py` merges the SQLite outputs above into `DB/all_time_entries.db` and exports `DB/all_time_entries.csv`.
- `scripts/private_time_entries.py` creates `DB/private.csv` with entries that do not already appear in `DB/all_time_entries.csv`.

Some scripts also use `DB/client_names.csv` as a local cache for task-to-client name resolution.

## Data outputs

Primary published outputs:

- `DB/all_time_entries.csv`: consolidated dataset used by reporting.
- `DB/tasks_table.csv`: task/project lookup exported from ClickUp.
- `DB/private.csv`: additional entries not already represented in the consolidated export.

Intermediate/local outputs:

- `DB/*.db`: SQLite files generated by each extraction stage.
- `DB/client_names.csv`: cache of resolved client names for tasks.

## Scheduling and automation

Automation is defined in [`.github/workflows/update_time_entries.yml`](.github/workflows/update_time_entries.yml).

Current workflow behavior:

- It runs on weekdays using the cron expression `0 7 * * 1,2,3,4,5`.
- It can also be started manually with `workflow_dispatch`.
- It installs Python, runs the extraction scripts in sequence, uploads artifacts, and commits updated CSV files back to `main`.

Important detail: GitHub Actions cron schedules are evaluated in UTC. The current cron value is `07:00 UTC`, which is not the same as a fixed `4:00 AM` local time. If the business requirement is specifically `4:00 AM` in Toronto or Eastern time, the cron schedule should be adjusted explicitly for that timezone behavior.

## Runtime requirements

The scripts expect:

- A ClickUp API token in environment variables.
- Write access to the `DB/` directory.
- Python dependencies required by the scripts, including `requests`, `pandas`, `python-dotenv`, and `pytz`.

## End-to-end flow

1. Read team members from ClickUp.
2. Pull tasks and time entries from the relevant ClickUp spaces/lists.
3. Persist raw/intermediate results into SQLite and CSV files in `DB/`.
4. Merge category-specific outputs into `DB/all_time_entries.csv`.
5. Commit the updated CSV files to GitHub from the scheduled workflow.
6. Refresh the Power BI report manually so it reads the latest files from GitHub.
